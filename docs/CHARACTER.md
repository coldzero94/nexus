## 1. 컨셉 한 장

**무엇인가** — 당신의 '움직임'을 양분 삼아 자라는 **작은 동반 몬스터**. **포켓몬·디지몬처럼 애착을 갖고 키워나가는 육성형 크리처**(새 형태 아님 — Finch류의 정적 마스코트와 구분). IP 없는 오리지널 캐릭터의 애착 한계는 외모가 아니라 **'능력치로 시각화된 내 기록'**에 애착을 두어 극복한다 — 걷기·러닝·근력이 이 아이의 지구력·민첩·힘·외형·기억으로 새겨지고, 쌓일수록 대체 불가능해지는 데이터 자산이 된다. 알에서 부화해 성장 단계를 밟는 육성 서사와 잘 맞는다.

**톤 — 장난기 중심 (다정 기저)** — 기본 말투는 반말·감탄사·이모지 섞인 개구쟁이. 단 진지한 순간(성취·복귀)엔 톤을 살짝 낮춰 진심을 보인다. **금지**: 잔소리, 죄책감 유발, 수치 나열식 훈계. 장난기가 표면, 다정이 바닥.

**세계관 한 문단** — 이 생물은 사용자를 대신해 세계를 조금씩 탐험하는 동행자다. 매일의 활동이 아이의 능력치로 새겨지고, 세계는 **원정**으로 열리며, 아이는 그 여정에서 이야깃거리를 물어온다. **벌은 없다** — 쉬는 날엔 같이 뒹굴고, 오래 못 봐도 돌아오면 폴짝 뛰어 반긴다. 죽지 않고, 퇴화하지 않으며, 유일한 소프트 손실은 '컨디션'뿐(회복 가능).

**애착 설계** — 온보딩 첫 3분 안에 "이 아이는 **내 운동으로만** 자란다"는 의존 관계를 각인(Finch 차용). 과거 이력 소급으로 "이미 이만큼 함께였어요" 연출.

**아트 방향** — 작은 동반 몬스터, 육성형 크리처, 2D · 새 형태 지양. 스펙: 기본체 1종 × **포즈 8종** × 장비 2슬롯 × 4~6종. **반응 다양성 우선**(Pokémon Sleep 이탈 원인 = 같은 애니메이션 소진).

포즈는 기분 5종의 기본 표정(`calm_smile`·`jump_hyped`·`proud_sparkle`·`bored_lookaround`·`cozy_roll`)에 **운동 종류별 특화 반응 3종**(#114 — `walk_along`·`run_along`·`flex`)을 더한 것이다. 기분과 표정은 더 이상 1:1이 아니다 — 같은 '신남'이라도 러닝한 날은 `run_along`, 개인계수가 튄 날은 `jump_hyped`다. 96×96 평면 치비라 회전이 없어서 종류는 자세가 아니라 **소품 하나**로 읽힌다: 걷기=발자국 궤적, 러닝=속도선, 근력=알통.

**구현: 손으로 쓴 VectorDrawable** (#66, 2026-08-03). AI 래스터 대신 벡터를 택한 이유 — ① 위젯 56dp·홈 히어로 140dp·성장 인라인 56dp를 **한 파일**로 쓴다 ② 파일당 ~2.5KB(168px ARGB 비트맵 113KB 대비) ③ 설정 비의존이라 `drawable-night` 변형이 없고, 그게 위젯 비트맵 캐시(#246)의 성립 전제다 ④ 장비 레이어 규약(`character_{state}_{frame}`)에 그대로 얹힌다.

스타일 일관성은 생성 시드가 아니라 **생성기**가 보장한다 — `tools/character_assets.py`가 몸을 한 번 정의하고 표정만 갈아끼운다. 팔레트·비율 변경은 한 줄이고, 아홉 파일이 함께 움직인다. **드로어블을 손으로 고치지 말고 생성기를 고칠 것.**

에셋 추가는 여전히 세 곳이 맞물려야 한다: 드로어블 + `animations.json` 상태 + (표정이면) `mood_triggers.json`의 `face`. 하나라도 빠지면 **조용히 기본 상태로 폴백**한다 — `MoodFaceAssetTest`가 그 세 곳을 고정한다.

**장비 8종 (#76, 슬롯 2×4)** — 머리: 밀짚모자·털모자·잎사귀 머리띠·새싹 왕관 / 장식: 빨간 목도리·방울 목걸이·잎사귀 펜던트·옆주머니. 같은 생성기가 만들고 `equipment.json`이 카탈로그다(추가 = JSON + 드로어블, 코드 무수정).

장비는 본체 위에 `matchParentSize`로 겹치므로 **같은 96×96 좌표계**를 쓴다. 기준: 머리 돔 꼭대기 y≈22, 중심 x=48. HEAD는 y 12~34, ACCESSORY는 **y 64~80**에 앉힌다 — 처음 y 56에 뒀더니 목도리가 입(y≈59)을 통째로 덮어 표정이 사라졌다. 장비도 해석 실패 시 조용히 버려지므로(`mapNotNull`) `EquipAssetTest`가 카탈로그·아트·이름 충돌을 고정한다.

**부화 4컷 (#110)** — `egg_0`(알) → `egg_1`(금) → `egg_2`(균열) → `egg_3`(깨어남). 알 중심을 캐릭터 몸 중심(48, 51)에 맞춰야 마지막 컷에서 껍데기 사이로 몸이 이어져 보인다. 프레임이 아니라 **상태 4개**다 — 씬이 진행을 제어하며 하나씩 갈아끼운다. 티커에 맡기면 리듀스드모션에서 통째로 멈춰 서사가 끊긴다.

배지 글리프 5종은 #266에서 이미 랜딩했다(`badge_*`, 획득/잠금 시각 상태 포함).

## 2. 기분 판정 — 결정 트리 (우선순위)

평가기는 매 정산/앱 진입 시 아래를 **위에서부터** 평가하고 **첫 매치**로 기분을 정한다.

```
0. returning(3일+ 공백 후 첫 실행)  → [복귀 환영 씬 E4-6] → 이후 신남/뿌듯으로 진입
1. 오늘 성취 이벤트 있음             → 뿌듯
   (leveledUp OR newBadge OR weeklyGoalMet OR newRecord)
2. 오늘 활동함 (todayActiveMin > 0)
   2a. personalCoef ≥ 1.3  OR  고강도(러닝/근력 세션)  → 신남 (jump_hyped)
   2b. 오늘 10분+ 하고 가장 많이 한 종류가 러닝         → 신남 (run_along)
   2c. 〃 근력                                        → 뿌듯 (flex)
   2d. 〃 걷기                                        → 평온 (walk_along)
   2e. 그 외 (전 종류 10분 미만)                       → 평온 (calm_smile)
3. 오늘 활동 안 함
   3a. restMode ON  OR  계획된 휴식(직전 리듬상 균형 휴식)  → 휴식 중
   3b. 그 외 (공백, 비휴식)                                → 심심
```

> **핵심 규칙**: 활동(2)은 휴식 모드보다 우선 — 휴식 모드여도 운동하면 신남/평온. 성취(1)는 활동 기분보다 우선.

> **성취(1)는 '넘긴 날 하루'다** (#114). 주간 활동일 수는 주 안에서 줄지 않으므로 `weeklyGoalMet`을 "이번 주 달성"으로 두면 넘긴 뒤 남은 요일 내내 1이 이겨서, **매일 운동하는 사용자일수록 반응 다양성을 못 본다**(주 4일 목표 기준 7일 중 4일). 그래서 `weeklyGoalMet`은 "오늘 넘겼다"로 판정한다.

## 3. 기분 트리거 표 (8행)

| 기분 | 트리거 조건 | 컨디션 영향 | 표정 | 대사 예시 (장난기 톤) |
|---|---|---|---|---|
| **뿌듯** | 오늘 성취 이벤트: `leveledUp` \| `newBadge` \| `weeklyGoalMet` \| `newRecord` | 중립 | 가슴 펴고 반짝 | "봤어 봤어?! 우리 레벨업했어 ✨" · "이 배지 내가 딴 거 맞지?! 😤" |
| **신남** | `todayActiveMin>0` **AND** (`personalCoef≥1.3` \| 고강도 세션) | 소폭 회복 | 방방 점프 | "오늘 좀 미쳤는데?! 🔥" · "헉헉— 근데 개운해 😆" |
| **신남**(러닝) | `runMin≥10` **AND** 셋 중 최다 | 소폭 회복 | 옆에서 같이 뜀(속도선) | "나도 옆에서 같이 뛰었어 — 봤어? 🏃" · "바람 가르는 거 이 맛이지 😤" |
| **뿌듯**(근력) | `strengthMin≥10` **AND** 셋 중 최다 | 유지·소폭 회복 | 알통 자랑 | "알통 봐봐. 이거 우리 거야 💪" · "오늘 좀 단단해진 것 같은데?" |
| **평온**(걷기) | `walkMin≥10` **AND** 셋 중 최다 | 유지·소폭 회복 | 따라 산책(발자국) | "나도 뒤에서 졸졸 따라갔어 🐾" · "산책 코스 괜찮더라 그치?" |
| **평온** | `todayActiveMin>0` (전 종류 10분 미만) | 유지·소폭 회복 | 잔잔한 미소 | "무난하고 좋았어 🙂" · "딱 적당했다 그치?" |
| **휴식 중** | 활동 없음 **AND** (`restMode ON` \| 계획된 휴식) | **하락 없음** | 이불 속 뒹굴 | "오늘은 공식 뒹굴데이 🛏️" · "쉬는 것도 훈련이라구~ 😏" |
| **심심** | 활동 없음 **AND** `restMode OFF` (공백) | 완만 하락(소프트) | 두리번·발 까딱 | "심심해~ 슬슬 나갈까? 👀" · "나 여기서 기다리는 중… 🐾" |

**복귀 환영** (E4-6, 별도 씬 · 기분 아님): `returning`=3일+ 공백 후 첫 실행 → 환영 컷 → 신남/뿌듯 진입.
대사: "왔다!! 어디 갔었어~ 보고 싶었잖아 🥹→😆". **삐짐은 1초, 반가움이 주. 처벌 없음.**

> 심심의 소프트 하락이 **유일한 손실 기제**(MVP 원칙). 캐릭터는 죽지 않는다. 심심 대사는 그리움·장난이지 잔소리가 아니다.

## 4. 평가기 입력 계약 (E4-4)

| 변수 | 타입 | 의미 |
|---|---|---|
| `daysSinceActivity` | int | 마지막 활동 이후 경과일 (0=오늘 활동) |
| `restMode` | bool | 사용자 휴식 모드 ON |
| `todayActiveMin` | int | 오늘 총 활동 분 (= 아래 셋의 합) |
| `walkMin` `runMin` `strengthMin` | int | 오늘 종류별 활동 분 (#114). 불리언 플래그가 아니라 **분**인 이유: 러닝 40분 + 근력 5분인 날에 알통이 뜨면 "내가 한 운동을 얘가 안다"가 오히려 깨진다 — 우세 판정을 표가 한다 |
| `personalCoef` | float(0.8–1.5) | 오늘 개인계수 (XP 산식) |
| `leveledUp` `newBadge` `weeklyGoalMet` `newRecord` | bool | 오늘 정산 성취 이벤트 |
| `condition` | int(0–100) | 현재 컨디션 |
| `returning` | bool | 3일+ 공백 후 첫 실행 (복귀 씬) |
| `timeOfDay` | enum(아침/낮/저녁) | 대사 변주용(선택) |

**실제로 도는 표는 앱 에셋** [`kotlin/app/src/main/assets/character/mood_triggers.json`](../kotlin/app/src/main/assets/character/mood_triggers.json)이다 — **표만 고치면 코드 수정 없이 반영**(E4-4 완료 기준). [`assets/mood_triggers_v1.json`](./assets/mood_triggers_v1.json)은 #65 산출 시점의 **5종 원안 스냅샷**이고 더 이상 최신이 아니다(#114에서 8행이 됐다). 고칠 곳은 앱 에셋 쪽이다.

새 변수를 추가할 때만 코드가 필요하다: `MoodContext` 필드 + `toVars()` + `VARS` 세 곳. `VARS`에 없는 식별자는 표 **로드 시점에** 예외로 걸린다(오탈자가 런타임에 조용히 매치 실패하지 않게).

## 5. 미확정 (다음 라운드)
- 캐릭터 **이름·종족** 확정 (후보 브레인스토밍 별도)
- 표정 5종 이상의 **대사 풀** 확장 (반응 다양성 — 표정당 3~5개, S4 P-2에서)
- '고강도 세션' 정의 수치화 (러닝 N분 이상 / 심박존 기준 — XP 산식과 정합)
- '계획된 휴식' 판정 로직 (직전 균형 리듬 기반)
