# 알파 게이트 측정 (#229, E15-1)

기준일 2026-07-27. **게이트 판정의 단일 기준 문서** — MVP §9·SPRINTS의 "D14에 테스터 절반이 주 3회+ 오픈"을 측정 가능한 절차로 고정한다. 정의가 없으면 게이트는 주관적 인상으로 붕괴하고, 게이트 측정 가능성이 곧 알파의 존재 이유다.

관련: `docs/MVP.md §9`(로드맵·게이트) · `docs/SPRINTS.md`(게이트와 그 이후) · `docs/OPS.md §2`(주간 루틴) · `docs/PRIVACY.md` · #74(closed test 14일 시계 운영)

## 1. 조작적 정의

| 용어 | 정의 |
|---|---|
| **D0** | closed test 개시일 — **전원 공통**(첫 배포일). 늦게 설치한 테스터도 같은 D0을 쓰되, 설치일을 로스터 `installed_on`에 적어 판정 시 참작한다. |
| **판정창** | D0부터 **14일**. 주 1 = D0~D6, 주 2 = D7~D13. |
| **오픈 1회** | 그 날짜에 앱을 **한 번 이상** 열었음. 같은 날 여러 번 열어도 1회(빈도 조작 방지). |
| **주 3회+** | 한 7일 구간에서 앱을 연 **서로 다른 날짜 수 ≥ 3**. |
| **분모** | **D0 시점에 옵트인한 인원**(목표 12명). 12명 미만으로 시작하면 그 수가 분모이며 판정 코멘트에 명시한다. |
| **절반** | 분모의 **과반**(12명이면 ≥ 6명)이 **주 2**에서 "주 3회+"를 만족. |
| **게이트 통과** | 위 "절반" 충족. 미충족 시 S8+로 가지 않고 코어 루프를 고친다(SPRINTS). |

**주 정의에 관한 메모(AC와의 차이)**: 티켓 AC는 "ISO주"라고 적었으나, 실제로는 **D0 기준 7일 구간**을 쓴다 — 배포가 주 중간에 시작되면 ISO주 첫 구간이 1~2일밖에 안 돼 판정이 왜곡되기 때문. 계획대로 D0이 월요일(2026-10-26)이면 두 정의는 **완전히 일치**하므로 기본 시나리오에서 차이가 없고, 일정이 밀려 D0이 월요일이 아닐 때만 이 규칙이 의미를 갖는다.

**주 2로 판정하는 이유(원문보다 엄격)**: 주 1에는 설치 직후 신기함(novelty)이 섞여 지속 사용을 과대평가한다. MVP·SPRINTS 문구("테스터 절반이 주 3회+")보다 **의도적으로 더 엄격한** 기준이며, 주 1은 참고 지표로만 본다.

**중도 이탈자**: 설치 후 이탈한 테스터는 **분모에 남긴다**. 이탈도 게이트가 재려는 신호의 일부다. 사유는 로스터 `note`에 적어 no-go 원인 분석에 쓴다.

## 2. 리드아웃 — 무엇을 근거로 판정하는가

세 소스를 쓰되, **온디바이스 카운터가 1급**이다.

| 순위 | 소스 | 역할 | 한계 |
|---|---|---|---|
| **① 온디바이스 카운터** | 설정 화면의 "이번 주 연 날짜: N일"(#286으로 구현) | 테스터가 **읽어서 알려주는 사실값** — 기억에 의존하지 않음 | 기기 밖으로 나가지 않으므로 테스터가 직접 알려줘야 함 |
| **② TelemetryDeck** | 리텐션·활성 사용자(SDK가 해시 식별자로 코호트 산출) | 추세·이상 감지, ①의 개연성 대조 | 대시보드가 제공하는 뷰에 한정 — **D0 전에 실제로 어떤 질의가 가능한지 확인해 이 표를 갱신할 것** |
| **③ 로스터** | 아래 템플릿 | ①의 응답을 모아 판정 계산에 쓰는 장부 | 응답이 있어야 채워짐 |

**왜 온디바이스 카운터인가**: 사용자별 "서로 다른 날짜 수"를 서버에서 세려면 계측에 식별자·날짜를 실어야 하는데, 이는 occurrence-only 원칙과 충돌한다. 반대로 기기 안에서 세면 데이터가 나가지 않고(불변식을 더 강하게 지킴), 회상 편향도 사라진다. 계측 이벤트는 추가하지 않는다.

> **선행 확인(D0 전 필수)**: TelemetryDeck 대시보드에서 리텐션 뷰가 실제로 무엇을 보여주는지 열어 보고 ②의 한계 칸을 사실로 갱신한다. `STACK.md §1`은 이 SDK가 "리텐션·세션 빌트인, 식별자 해시"라고 적고 있으므로, 아래 §6의 D1/D3/D7이 대시보드에서 그대로 읽힐 가능성이 있다 — 읽히면 ②의 순위를 올린다.

## 3. 로스터 템플릿

`docs/assets/alpha-roster.csv`를 **로컬 사본**으로 복사해 쓴다(아래 §4 게시 규칙 참고).

```
tester_id,installed_on,responded_w1,week1_days,responded_w2,week2_days,week2_meets_3plus,note
```

- `tester_id`: T01~T12 익명 ID. 실명·연락처·기기명은 **어디에도 적지 않는다**. 매핑표는 팀 비밀번호 관리자에.
- `responded_w1/w2`: `Y`/`N` — **무응답(N)과 "응답했고 0일"(Y + 0)은 뜻이 정반대**라 반드시 구분한다.
- `week2_meets_3plus`: `week2_days >= 3`이면 `Y`.
- `note`: **닫힌 어휘만** — `dropped` · `reinstalled` · `install_failed` · `device_changed`. 자유 서술 금지(재식별 경로).

**집계**: `week2_meets_3plus == Y` 개수 ≥ 과반 → **go**.

**무응답 처리**: 무응답자는 분자·분모 **양쪽에서 제외**하고, 응답률이 **2/3 미만이면 판정 보류**(inconclusive)로 기록한다 — 무응답을 자동 실패로 세면 침묵이 곧 no-go가 되어 게이트가 행동이 아니라 응답률을 재게 된다.

## 4. 게시 규칙 — 채워진 로스터는 공개 레포에 올리지 않는다

이 레포는 **공개**다. T01~T12는 익명이 아니라 **가명**이며(매핑표가 존재), 주별 앱 오픈 일수는 개인 행동 데이터다. 되돌릴 수 없는 공개가 되지 않도록:

- **레포에 커밋하는 것**: 빈 템플릿(`docs/assets/alpha-roster.csv`)과 **집계 결과만**(예: "주 2 충족 7/12, 응답 11/12").
- **레포에 올리지 않는 것**: 채워진 로스터 파일, 테스터별 수치, `note`의 개별 사정. 로컬·비공개 채널에 둔다.
- **동의**: 테스터 온보딩(#74) 시 "주간 사용 일수를 익명 집계로 기록한다"를 고지하고 동의를 받는다.
- 판정 코멘트에도 개인별 수치를 쓰지 않는다 — 집계와 결론만.

## 5. 주간 절차 (OPS §2에 편입)

D0~D14 동안:

1. **금요일(중간 리마인더)**: 테스터에게 설정 화면의 "이번 주 연 날짜"를 봐 달라고 **DM으로** 개별 요청한다. 공개 채널에서 서로의 답이 보이면 사회적 바람직성 편향이 생기고, 판정 문턱("3일")을 답과 함께 노출하지 않는다.
2. **주 2 값은 D14에 수집한다** — 주 2는 D13(일요일)까지이므로 금요일(D11) 값으로 판정하면 **주말 이틀이 통째로 빠진다**. 걷기·러닝 앱에서 주말은 활동이 가장 많은 날이라 게이트가 장부 오차로 실패할 수 있다. 금요일은 리마인더, 확정 수집은 D14.
3. TelemetryDeck 활성 추세로 응답 총합의 개연성을 대조(크게 어긋나면 재확인).
4. **D14**: 로스터로 go/no-go를 판정하고 **#74 이슈에 코멘트**로 기록한다 — 판정 결과, 분모/충족 인원/응답률(집계만), 특이사항, no-go면 다음에 고칠 코어 루프 가설.

## 6. 리텐션 코호트 정의

게이트와 별개로 추세를 남긴다(공개 출시 전 기준선).

- **코호트 기준**: D0 코호트(알파 기간엔 단일 코호트).
- **로스터로 산출 가능**: **W1 · W2** — 각 7일 구간에 한 번이라도 열었는지(`weekN_days > 0`)의 비율.
- **TelemetryDeck 의존**: **D1 · D3 · D7** — 설치 후 경과일별 잔존율. 대시보드 리텐션 뷰에서 읽히면 기록하고, **읽히지 않으면 이 세 지점은 알파에서 측정하지 않는다**(로스터는 주 단위라 산출 불가). D0 전 선행 확인(§2) 결과에 따라 확정한다.
- **읽는 법**: D1 급락은 온보딩·권한 문제, D7 유지 후 W2 급락은 코어 루프의 반복 동기 부족을 시사한다. no-go 시 이 모양으로 원인 가설을 좁힌다.

## 7. 계측 불변식 (변경 금지)

- 이 문서의 어떤 측정도 **새 계측 이벤트를 요구하지 않는다** — 기존 `APP_OPENED`(occurrence-only)와 **기기 밖으로 나가지 않는** 온디바이스 카운터로 충족한다.
- 이벤트를 추가해야 한다면 `TelemetryEvent` enum + `TelemetryPolicyTest`의 고정 allowlist를 **같은 커밋에서** 갱신한다(CI가 강제).
- 페이로드에 건강 파생값(걸음·운동 시간·심박·XP·컨디션·레벨)·원시 타임스탬프·개인 식별자를 싣지 않는다.
- 테스터별 수치는 **공개 레포에 게시하지 않는다**(§4).
